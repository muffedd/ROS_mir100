================================================================
MiR100 SIMULATION MODEL - BOUNDED VALIDATION REPORT
Date: 2026-10-26. Model: mir100_ref (repo head at test time: 60d10c8
for the report; tests ran on 872d847, same model files).
Scope: simulation self-consistency only (command -> odometry ->
Gazebo ground truth). No physical MiR100 data has been collected,
so this is not hardware or digital-twin validation.
================================================================

----------------------------------------------------------------
1. HOW TO REPRODUCE (exact commands)
----------------------------------------------------------------
Terminal 1 (build once, then):
  source /opt/ros/jazzy/setup.bash && source install/setup.bash
  ros2 launch mir_description gazebo.launch.py gui:=false
Terminal 2 (bridges):
  source /opt/ros/jazzy/setup.bash && source install/setup.bash
  ros2 run ros_gz_bridge parameter_bridge \
    /clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock \
    /cmd_vel@geometry_msgs/msg/Twist]gz.msgs.Twist \
    /odom@nav_msgs/msg/Odometry[gz.msgs.Odometry
Terminal 3 (test harness, scripts/validate_model.py in this repo):
  python3 scripts/validate_model.py --mode straight --trials 3 --out /tmp/straight.csv
  python3 scripts/validate_model.py --mode turn --trials 3 --out /tmp/turn.csv
Method: the harness publishes a constant cmd_vel profile for a fixed
number of SIM seconds (uses /clock), then lets the robot settle for
3 sim-seconds. It logs commanded velocity, /odom, and Gazebo ground
truth (model pose from /world/empty/pose/info, read via gz transport)
to CSV. Each trial compares odometry vs ground truth between the
pre-drive and post-settle samples. Requirements: the mirsim-style
Python environment needs gz transport bindings (gz.transport13);
ROS 2 Jazzy + Gazebo Harmonic as in the main README.

----------------------------------------------------------------
2. STATIC CONFIGURATION AUDIT (actual runtime SDF)
----------------------------------------------------------------
Source: xacro -> URDF -> "gz sdf -p" (what the simulator loads).
- Footprint collision box: 0.9 x 0.58 m. OEM spec sheet: 890 x 580 mm.
  NOT exact: the model is 10 mm longer. Spec source (full URL):
  https://howtorobot.com/sites/default/files/2021-02/MiR100%E2%84%A2%20_%20Mobile%20Industrial%20Robots_0.pdf
- Drive wheel radius 0.0625 m = OEM nominal 125 mm diameter (nominal
  match only; no tolerance comparison).
- Wheel separation 0.4452 m; no public OEM figure found; unverified.
- Masses as loaded: base_footprint lump 62.0 kg (base_link 58.0 +
  the two laser links at a declared 2.0 kg each); 2 drive wheels at
  1.0 kg; 4 caster assemblies at ~1.31 kg. Total 69.239 kg vs OEM
  70 kg: 1.1% under, coincidental (declared approximations, not
  tuned to the spec sheet). Laser 2.0 kg values are pre-existing
  declared approximations without a cited datasheet.
- Decorative mirref visual links are massless (lumped at zero mass;
  valid URDF, zero dynamics impact by construction).
- Inertias: uniform-box formula (base), cylinder formula (wheels),
  explicit tensor (caster bases). Approximations.
- Drive: gz-sim DiffDrive; max linear accel 1.0 m/s^2; max angular
  accel 1.5 rad/s^2; odometry publish rate 50 Hz (configured).
- Friction: the model specifies no surface friction. The SDF default
  is mu = mu2 = 1.0 (SDFormat specification, link > friction element:
  http://sdformat.org/spec?ver=1.11&elem=link). Whether Gazebo
  Harmonic's physics engine applied exactly these defaults was NOT
  independently verified at runtime.
- Scanners: 2x gpu_lidar, 541 samples, -2.2689..+2.3562 rad (~265
  degrees), 0.05-29.0 m, 12.5 Hz configured target (achieved rate
  not measured). Earlier live checks on this model: zero self-hits;
  obstacle response within 0.03 m of geometric prediction.

----------------------------------------------------------------
3. RUNTIME RESULTS (measured)
----------------------------------------------------------------
STRAIGHT, 0.2 m/s for 10.0 sim-s, 3 trials (all identical):
  odometry 1.980 m | ground truth 1.985 m | odom-GT gap 0.005 m (0.25%)
  lateral drift 0.000 m | heading change 0.00 deg
  Command-vs-GT -0.75%, consistent with the 1.0 m/s^2 accel ramp.
TURN, 0.5 rad/s for 6.283 sim-s (commanded integral 180.0 deg):
  wheel-joint integral 175.0 deg (acceleration-ramp truncation);
  /odom reports 175.3 deg - odometry faithfully reports wheel rotation.
  Ground-truth body rotation, 4 observed trials:
    first turn after straight travel: 147.2 deg, 147.3 deg (2 trials)
    subsequent turns (casters already tangent): 164.0, 164.0 (2 trials)
  Wheel/body disagreement: 28 deg on a first turn, 11 deg steady-state.
  Instrumented run: caster swivels approach the correct tangent angles
  (within ~7 deg) but start straight-travel-aligned and scrub while
  swiveling in; drive wheels track commanded velocity exactly in cruise.
Interpretation (bounded): command -> wheels -> odometry is faithful.
The wheel/body disagreement is consistent with wheel-ground and caster
scrub slip at the default friction. Whether this matches real MiR100
physics is unknown (no hardware data collected).

----------------------------------------------------------------
4. KNOWN LIMITATIONS (all open)
----------------------------------------------------------------
- Rotation: the body under-rotates vs wheel odometry by ~6%
  steady-state and ~16% on the first turn after straight travel.
  Odometry-only rotation accuracy is limited accordingly.
- Single operating points tested (0.2 m/s; 0.5 rad/s); no speed sweep.
- Hard-map guided route: NOT validated as a continuous run. Legs
  passed across two interrupted driver sessions (4 legs, then 10 legs
  after restart); the first session sent 559 unexplained repeat goals
  to one waypoint (each instantly reported succeeded) before it was
  stopped; final ground-truth distance to the route goal was 0.589 m;
  no contact record exists. Ground-truth-derived waypoints were used;
  unexplored-map autonomy is not claimed.
- Conservative hard-test params (robot_radius 0.60 / inflation 0.90)
  have never completed a route; the passing legs used defaults
  (0.53 / 0.55).
- No physical data collected.
